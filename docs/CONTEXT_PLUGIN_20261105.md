# Локальный контекст-плагин `acv-context` — 2026-11-05

Задача: проект содержит сотни Markdown-файлов, инструкций и логов (индекс: 475 `.md`, 5230 чанков,
≈1.3 млн токенов по оценке `символы/3`; `logs/` ≈23 ГБ). Передавать их в промпт целиком нельзя.

## Что сделано

Плагин Claude Code `tools/acv-context/` (без внешних зависимостей, только stdlib и SQLite FTS5):

| Компонент | Назначение |
|---|---|
| `ctxlib.py` | Индекс FTS5 (BM25, porter+unicode61, заголовок весом 6:1), чанки по заголовкам Markdown с `path:строки`, инкрементальное обновление по mtime/size; дайджест логов; компактное дерево; сборщик контекста |
| `mcp_server.py` | MCP stdio: `ctx_search`, `ctx_log_digest`, `ctx_tree`, `ctx_assemble`, `ctx_reindex`; читает только внутри проекта, `.git` закрыт |
| `ctx.py` | То же из командной строки (`index`, `search`, `log`, `tree`, `assemble`, `stats`) |
| `hooks/hooks.json` | `SessionStart`: инкрементальное обновление индекса |
| `skills/project-context/SKILL.md` | Правило для модели: сначала `ctx_search`/`ctx_log_digest`, потом чтение файла |
| `.claude-plugin/plugin.json`, `.mcp.json` | Манифест и подключение сервера (`${CLAUDE_PLUGIN_ROOT}`) |

Индекс не включает пути из `.llmignore` ([tools/llmignore.py](tools/llmignore.py)); база лежит в
`${CLAUDE_PLUGIN_DATA}` (иначе `tmp/acv-context/index.sqlite`).

### Сборщик контекста (`ctx_assemble`)

1. Метаданные: дерево файлов без содержимого (скрытые `.llmignore`-пути только перечислены).
2. Санитайзер логов: срезает ANSI, временные метки и id потоков, сворачивает повторы (`x20`),
   нормализует числа и hex-адреса для группировки, ставит FATAL/ERR/WARN первыми; явный тег
   уровня (`[warning]`) важнее ключевых слов в тексте.
3. Бюджет, жёсткие потолки от `total_tokens`: архитектура (`kb:X360_PROJECT_STATE`, аргумент
   `state_file`) 15 %, код и рабочие файлы 60 % (включая найденные FTS заметки), логи 25 %.
   Неиспользованный остаток не переносится. Если файл не помещается, берутся окна вокруг слов запроса,
   иначе начало и конец. В архитектуре при нехватке места остаются разделы, релевантные запросу.

## База знаний в плагине

Документы проекта хранятся в SQLite `tools/acv-context/knowledge.sqlite3` (бывшая папка `docs/` перенесена целиком).
Копирования и синхронизации больше нет: `sync-docs` удалён. Ссылки в проекте переписаны на новый путь;
битых ссылок не добавлено (проверка до и после: 1412 → 1011, все оставшиеся были до переноса).

- Поиск и индекс работают по базе знаний; архивные документы (`status=archived`) исключены по умолчанию.
- Если плагин установлен вне этого репозитория, индекс берёт заметки из собственного каталога плагина
  (знания поставляются вместе с плагином).
- Резерв: `archive/docs-2026-11-06.tar.gz` (с SHA-256). Предыдущая копия бандла и скрипты миграции — в `tmp/docs-move/`.

## Ограничения

- Индекс только по Markdown; код и логи не индексируются (логи обрабатываются дайджестом по запросу,
  читается хвост до 4 МБ). Нет совпадения в `ctx_search` значит «нет в проиндексированных заметках».
- Поиск лексический: морфология русского грубая (отсечение окончания у слов длиннее 5 букв), синонимов
  и семантики нет. Эмбеддинги не использованы.
- Токены оцениваются как `символы/3`; на реальном токенайзере цифры будут другими.
- Экономия считана как «чтение целых файлов-источников против ответа поиска», это не измерение
  качества ответов модели. Сколько токенов реально экономится за сессию, не измерено.
- Дайджест логов группирует строки по нормализованному тексту; редкая важная строка с общим шаблоном
  может слиться с другими (поправка: счётчик `xN` и первая строка сохраняются).
