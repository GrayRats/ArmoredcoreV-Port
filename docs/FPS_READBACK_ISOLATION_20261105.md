# ACV: изоляция причины низкого FPS (readback / FSI) — 2026-11-05

Область: меню/титульная сцена первых ~170 с после старта, GPU NVIDIA GeForce GTX 1660 SUPER
(CLAUDE.md называет RX 6700 XT — фактически её нет), текущая сборка `acv_test_build`,
пользовательский `acv.config` без `--settings`, `limit=0`. Это не геймплей и не контролируемая
сцена: числа ниже сравнимы только между собой.

Метрика — `[acv-display] pacing` (среднее по 300 swap), поздняя фаза = окна, начавшиеся после
60 с. Один запуск на конфигурацию; разброс между запусками не измерялся. Метрика считает
guest swap, не уникальные кадры. GPU % — `nvidia-smi` раз в 2 с (под MangoHud: поток
`mangohud-nvidia` сам занимает ≈19 % ядра).

| Конфигурация | Поздняя фаза, swap/с | GPU util |
|---|---:|---:|
| `acv-fsi` (FSI + `readback_resolve=full` + `protect_zero=false`) на оригинале | 9.9 | — |
| то же, loose-корень | 10.9 | 75→88→92 % |
| `sdk` (ни FSI, ни readback) | 25.5 | 86→96→92 % |
| `sdk` + только FSI (`render_target_path_vulkan=fsi`) | 21.9 | 86→97→96 % |
| `sdk` + только `readback_resolve=full` | 11.1 | 85→94→92 % |
| `acv-fsi` + `readback_resolve=some` | 12.3 | 88→95→94 % |
| `acv-fsi` + `readback_resolve=fast` | 15.0 | 73→96→98 % |

Прогон `sdk` + `readback_resolve=full` без `protect_zero=false` упал с guest access violation
(fatal 5468), поэтому приведён повтор с `protect_zero=false`.

## Выводы

- CPU не узкое место: процесс ≈130–160 % всех потоков, главный ≈26 % ядра. GPU 92–98 % в поздней фазе.
- Основная потеря — `readback_resolve=full` (синхронный readback): 25.5 → 11.1 swap/с (≈2.3×).
  FSI-путь добавляет меньше: 25.5 → 21.9 (≈14 %). Вместе — 9.9.
- Отложенные режимы возвращают часть: `some` +≈20 %, `fast` +≈50 % относительно `full`; до
  уровня без readback не доходят, GPU остаётся насыщенным.
- Loose-корень не меняет FPS: оригинал и loose дают 9.9 и 10.9 с одинаковым спадом.
- Спад с ~35 swap/с (первые ~40 с) до ~10 происходит в обоих режимах; создание пайплайнов
  к этому времени закончено, в логе после ~30 с событий нет. Какая сцена даёт спад, не
  определено.

## Ограничения и что не доказано

- `readback_resolve` нужен игре: без полного readback RGBA-аллокация bake-текстур остаётся
  нулевой (см. комментарий в `probe_linux.py`). Корректность `some`/`fast` и `sdk`-профиля не
  проверялась — картинка не сравнивалась. Использовать эти результаты как рекомендацию нельзя.
- Не измерено, какая именно часть readback дорога: GPU-копии, синхронное ожидание fence или
  число resolve. Это можно выяснить профилировщиком `ACV_GPU_TIMESTAMPS`, которого нет в
  текущей сборке (кандидат из [FPS_GPU_TIMESTAMPS_20261103](kb:FPS_GPU_TIMESTAMPS_20261103)).
- Геймплей/миссия не запускались; в миссии распределение может быть иным.

## MangoHud

Собственный счётчик MangoHud («Host FPS», частота `vkQueuePresent`) считает показы окна,
которые повторяют последний guest-кадр, и не следует за частотой игры. Отключён
(`fps=0` в `tools/native-rexglue/acv_mangohud.py`); остаётся строка Guest. Её ограничение:
она обновляется раз в 300 swap — при 10 swap/с это ≈30 с, при 9 swap/с строка показывала
значение с возрастом 25 с. Для быстрого отклика нужен time-based интервал в
`command_processor.cpp` (патч SDK и пересборка runtime), в этой работе не делался.
